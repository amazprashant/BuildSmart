What is RAG?

Retrieval-Augmented Generation is a technique that enhances LLM responses by retrieving relevant documents from an external knowledge base at query time, then providing those documents as context to the model.

Core idea:

Instead of relying solely on what the LLM learned during training, RAG retrieves up-to-date, domain-specific information and injects it into the prompt. The LLM then generates answers grounded in this retrieved context.

🚫

Without RAG

LLM answers from training data only. Hallucinations, stale information, no domain specificity.

✅

With RAG

LLM answers grounded in your documents. Accurate, up-to-date, citable sources.

⚙️

vs. Fine-tuning

RAG is cheaper, faster to update, and doesn't require retraining. Fine-tuning teaches style/format; RAG teaches facts.

RAG Pipeline

RAG has two distinct pipelines that run at different times:

Indexing Pipeline (offline — runs once)

Raw Documents (PDFs, Word docs, web pages, databases) │ ▼ 1. Document Loading Load and parse raw documents into text │ ▼ 2. Text Splitting / Chunking Split into overlapping chunks (e.g., 500 tokens, 50-token overlap) │ ▼ 3. Embedding Generation Convert each chunk to a vector using an embedding model (OpenAI text-embedding-3-small, sentence-transformers, etc.) │ ▼ 4. Vector Store Indexing Store <chunk_text, embedding> pairs in a vector database (Pinecone, Qdrant, Chroma, pgvector, FAISS)

Query Pipeline (online — runs per user question)

User Question: "What is our refund policy?" │ ▼ 1. Query Embedding Embed the question using the same embedding model │ ▼ 2. Similarity Search Find top-K most similar chunks in the vector store (cosine similarity, dot product) │ ▼ 3. Context Assembly Combine retrieved chunks into a context block │ ▼ 4. Prompt Construction System prompt + context + user question │ ▼ 5. LLM Generation LLM generates answer grounded in retrieved context │ ▼ Answer: "According to our policy, refunds are processed within 7 days..."

Chunking Strategies

How you split documents significantly impacts retrieval quality. Chunks too large → irrelevant noise in context. Chunks too small → missing context for answering.

StrategyDescriptionBest For
Fixed-sizeSplit by token/character count with overlapGeneral purpose, simple docs
Sentence-basedSplit at sentence boundariesProse, articles, Q&A docs
RecursiveSplit by paragraphs, then sentences, then wordsMixed-format docs (default LangChain)
SemanticSplit when topic changes (embedding-based)Long docs with distinct sections
Document-specificRespect markdown headers, code blocks, tablesStructured docs (MDX, Notion)
Chunk size rule of thumb:

Start with 500-1000 tokens per chunk, 10-15% overlap. Evaluate retrieval quality on your specific documents and adjust. There's no universal ideal.

Critical:

Use the same embedding model for both indexing and querying. Mixing models will produce meaningless similarity scores.

Retrieval Techniques

1. Dense Retrieval (Vector Similarity)

Embed query and find nearest chunks by cosine similarity. Captures semantic meaning — "automobile" matches "car". The standard RAG approach.

2. Sparse Retrieval (BM25 / Keyword)

Traditional TF-IDF based keyword matching. Works well for exact terms, product codes, proper nouns that embeddings might miss.

3. Hybrid Retrieval

Combine dense + sparse with Reciprocal Rank Fusion (RRF). Best of both worlds — recommended for production RAG.

4. Re-ranking

After initial retrieval (top-20), pass candidates through a cross-encoder re-ranker to get the truly relevant top-5. Significantly improves precision.

from langchain.retrievers import EnsembleRetriever, BM25Retriever

RAG Evaluation Metrics (RAGAS)

MetricWhat It MeasuresRange
FaithfulnessAre claims in the answer supported by the retrieved context?0–1 (higher better)
Answer RelevancyDoes the answer address the user's question?0–1
Context PrecisionAre retrieved chunks relevant? (precision of retrieval)0–1
Context RecallDid retrieval find all necessary chunks?0–1
RAGAS library:

The open-source RAGAS framework automates all four metrics using an LLM as a judge. Run it on a golden dataset of 20-50 question-answer pairs to measure pipeline quality.

RAG Types

🔰

Naive RAG

Basic index → retrieve → generate pipeline. Good starting point.

⚙️

Advanced RAG

Adds query rewriting, re-ranking, hybrid search, metadata filtering.

🔀

Modular RAG

Swappable components. Mix and match retrievers, generators, feedback loops.

🤖

Agentic RAG

LLM decides when and how to retrieve. Multiple retrieval steps, tool use.
