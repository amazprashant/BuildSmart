Indexing Pipeline — Step by Step

1

Document Loading

Read raw files and extract text. Support PDF, Word, HTML, Markdown, CSV, databases. Tools: LangChain PyPDFLoader, UnstructuredLoader, DirectoryLoader.

2

Text Chunking

Split documents into overlapping chunks. Typical: 500-1000 tokens per chunk, 10-15% overlap. Preserve sentence/paragraph boundaries where possible. Add metadata (source file, page number, section).

3

Embedding Generation

Convert each chunk to a dense vector using an embedding model. The vector captures semantic meaning — similar content produces similar vectors. Dimensions: 384 to 3072 depending on model.

4

Vector Store Indexing

Store (chunk_text, embedding, metadata) in a vector database. Common choices: Pinecone (managed), Qdrant (self-hosted), Chroma (local dev), pgvector (Postgres extension).

Query Pipeline — Step by Step

1

Query Pre-processing (Optional)

Improve retrieval by: query rewriting (expand to multiple questions), HyDE (generate a hypothetical answer and embed it), decomposition (break complex questions into sub-questions).

2

Query Embedding

Embed the user's question with the same model used during indexing. This produces a query vector in the same semantic space as the stored chunks.

3

Similarity Search (Retrieval)

Find the K most similar chunks using cosine similarity or dot product. Typical K=5 to 10. Optional: filter by metadata (date range, document type, department).

4

Re-ranking (Optional)

Pass the top-20 candidates through a cross-encoder model to re-score and keep only the truly relevant top-5. Significantly improves precision. Models: Cohere Rerank, cross-encoder/ms-marco-MiniLM-L-6-v2.

5

Prompt Construction

Assemble: system instructions + retrieved chunks (context) + conversation history + user question. Total must fit within LLM's context window.

6

LLM Generation

The LLM synthesizes an answer using only the provided context. Well-designed prompts instruct the model to cite sources and say "I don't know" if the context doesn't contain the answer.

The Prompt Template

SYSTEM:
You are a helpful assistant. Answer questions based ONLY on the provided context.
If the context doesn't contain the answer, say "I don't have enough information."
Always cite the source document when providing facts.

CONTEXT:
[Retrieved chunk 1 — source: policy_document.pdf, page 3]
"Refunds are processed within 7 business days of the return receipt..."

[Retrieved chunk 2 — source: faq.html, section: returns]
"Customers must initiate returns within 30 days of purchase..."

USER QUESTION:
How long do I have to return an item and how long will the refund take?

ASSISTANT:
Based on our policy (faq.html), you have 30 days from purchase to initiate a return.
Once we receive the returned item, the refund is processed within 7 business days (policy_document.pdf, p.3).

Where RAG Goes Wrong

ProblemSymptomFix
Bad chunkingContext cut mid-sentence; missing key infoAdjust chunk size/overlap, use semantic splitting
Wrong embedding modelRetrieval misses relevant docsEvaluate on your domain; try multiple models
Low K (too few chunks)Answer missing important detailsIncrease K; add re-ranker
High K (too many chunks)Irrelevant noise in context; LLM confusedUse re-ranking; metadata filtering
Prompt too longContext window exceeded; truncated chunksSummarize retrieved docs before inserting
LLM hallucinates anywayAdds facts not in contextExplicit system instructions + faithfulness check
Evaluation is key:

Build a golden Q&A test set (20-50 examples) and measure RAGAS metrics (Faithfulness, Context Precision, Answer Relevancy) after every pipeline change. Don't optimize blindly.
