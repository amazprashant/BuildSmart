Section 01

Why Build a Custom MCP Client?

All previous videos used Claude Desktop as the ready-made client. But real-world AI applications need their own clients. If you're building a chatbot, a web app, or an automation agent, you need to programmatically connect to MCP servers.

Claude Desktop (Used So Far)

Type: Ready-made host + client by Anthropic
LLM: Only Claude — no GPT-4, Gemini, Llama
UI: Fixed Anthropic-provided chat interface
Control: Limited — configure servers only
Embedding: Cannot embed in your own app
Deployment: Desktop app only

Custom Client (This Video)

Type: Your own Python code using a library
LLM: Any — GPT-4, Claude API, Gemini, local
UI: Any UI: Streamlit, React, FastAPI, mobile
Control: Full — you own the entire flow
Embedding: Embed in any product or service
Deployment: Web, cloud, Dockerized, serverless
The key shift: Building your own client means any chatbot you create can talk to any MCP server in the world. Your personal assistant becomes truly universal — add math tools, expense tracking, code execution, 3D animation, web search — all from one chat interface you control.
Section 02

Library Choice — langchain-mcp-adapters

Three options exist for building MCP clients in Python. All three were evaluated and langchain-mcp-adapters was chosen for the simplest and most practical path.

📘

Option A — Official MCP SDK

Anthropic's own Python mcp library. Lowest level — maximum protocol control. More boilerplate needed to wire an LLM to the tools.

⚡

Option B — fastmcp Client

fastmcp also has client capabilities. Consistent with server-side fastmcp code. Good choice if already deep in fastmcp ecosystem.

✅

Option C — langchain-mcp-adapters ← Chosen

Why: Simplest approach — minimal code. Plus: integrates natively with LangChain/LangGraph, auto-converts MCP tools into LangChain StructuredTool objects that work with llm.bind_tools().

What it does under the hood: langchain-mcp-adapters is described as "a lightweight wrapper that makes MCP tools compatible with LangChain and LangGraph." It handles all MCP protocol communication and schema conversion — you just call get_tools() and get standard LangChain tools back.

Section 05

The Math Server (Local) — Preview & Code

Before building the client, the Math server is tested in MCP Inspector to confirm it runs properly. The server has 6 tools built with fastmcp.

# mcp-math-server/main.py
from fastmcp import FastMCP

mcp = FastMCP("math-server")

@mcp.tool()
def add(a: float, b: float) -> float:
    """Add two numbers."""
    return a + b

@mcp.tool()
def subtract(a: float, b: float) -> float:
    """Subtract b from a."""
    return a - b

@mcp.tool()
def multiply(a: float, b: float) -> float:
    """Multiply two numbers."""
    return a * b

@mcp.tool()
def divide(a: float, b: float) -> float:
    """Divide a by b."""
    return a / b

@mcp.tool()
def power(base: float, exp: float) -> float:
    """Raise base to exp."""
    return base ** exp

@mcp.tool()
def modulo(a: int, b: int) -> int:
    """Return remainder of a / b."""
    return a % b

if __name__ == "__main__":
    mcp.run()  # stdio transport — local server
MCP Inspector test: uv run fastmcp dev main.py → Connect → Tools → List Tools shows 6 tools. Test: modulo(21, 7) → 0. Server confirmed working.
Section 06

Client 1 — Connect + Fetch Tools

The client is built incrementally. Step one: connect to the Math server, discover its tools, and store them in a usable dictionary format.

# client1.py — Stage 1: Connect and fetch tools
import asyncio
from langchain_mcp_adapters.client import MultiServerMCPClient
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.messages import ToolMessage
load_dotenv()

# ── Server Configuration ─────────────────────────────────────────────
# Same format as Claude Desktop's claude_desktop_config.json!
# "math"      = name we assign to this server
# transport   = "stdio" because it runs locally on this machine
servers = {
    "math": {
        "transport": "stdio",
        "command": "/usr/local/bin/uv",  # abs path (which uv)
        "args": [
            "run", "fastmcp", "run",
            "/home/user/Desktop/mcp-math-server/main.py"
        ]
    }
}

async def main():
    # Step 1: Create the multi-server client
    client = MultiServerMCPClient(servers=servers)

    # Step 2: Fetch all tools — returns List[StructuredTool]
    # Client automatically starts the Math server as a subprocess
    tools = await client.get_tools()

    # Step 3: Build named_tools dict for easy lookup
    # Format: { "add": , "multiply": , ... }
    named_tools = {tool.name: tool for tool in tools}
    print(list(named_tools.keys()))
    # Output: ['add', 'subtract', 'multiply', 'divide', 'power', 'modulo']

asyncio.run(main())
Important — Use absolute paths: The client spawns the server as a child process. Use which uv (Mac/Linux) to get uv's absolute path. Use the full path to main.py. Relative paths will fail if the working directory differs.
Section 07

The Full 6-Step Tool Call Flow

This is the core of the MCP client. When a user asks a question that needs a tool, the flow follows exactly 6 steps. Every step maps to a specific piece of code.

// The 6-step MCP tool call cycle
# client1.py — Full 6-step tool call flow
async def main():
    client = MultiServerMCPClient(servers=servers)
    tools = await client.get_tools()
    named_tools = {t.name: t for t in tools}

    # ── ①② LLM with tools ────────────────────────────────────────────────
    llm = ChatOpenAI(model="gpt-4")
    llm_with_tools = llm.bind_tools(tools)  # pass the LIST, not dict

    # ── ① Send prompt ────────────────────────────────────────────────────
    prompt = "Using the math tool, what is the product of 12 and 15?"
    response = await llm_with_tools.ainvoke(prompt)
    # response.content = ""  (empty = tool call needed)
    # response.tool_calls = [{"name":"multiply","args":{"a":12,"b":15},"id":"..."}]

    # ── ② Check if tool needed ───────────────────────────────────────────
    if not response.tool_calls:
        print(response.content)  # direct answer (no tool)
        return

    # ── ③ Extract tool name, args, ID ────────────────────────────────────
    tool_call = response.tool_calls[0]           # first tool call
    selected_tool      = tool_call["name"]      # "multiply"
    selected_tool_args = tool_call["args"]      # {"a": 12, "b": 15}
    selected_tool_id   = tool_call["id"]       # "call_abc123"

    # ── ④ Execute the tool via MCP ───────────────────────────────────────
    tool_result = await named_tools[selected_tool].ainvoke(selected_tool_args)
    # tool_result = 180

    # ── ⑤ Wrap result in ToolMessage ─────────────────────────────────────
    tool_message = ToolMessage(
        content=str(tool_result),
        tool_call_id=selected_tool_id  # must match ③'s id
    )

    # ── ⑥ Send full history back → get final answer ──────────────────────
    final_response = await llm_with_tools.ainvoke(
        [prompt, response, tool_message]  # full conversation history
    )
    print(final_response.content)
    # "The product of 12 and 15 is 180."

asyncio.run(main())

Section 08

Handling Tool vs Non-Tool Queries

When the user asks a general question ("What is the capital of India?"), no MCP tool is needed. Without the guard clause, the code crashes because response.tool_calls is empty.

✅ Non-Tool Query

Prompt: "What is the capital of India?"

response.tool_calls is empty → print response.content ("New Delhi") → return immediately. No MCP server involved at all.

🔧 Tool Query

Prompt: "What is the remainder of 2314 ÷ 7?"

response.tool_calls has an entry → execute 6-step flow → modulo(2314, 7) = 2 → "The remainder is 2."

# The guard clause that makes both cases work
response = await llm_with_tools.ainvoke(prompt)

if not response.tool_calls:
    # ─ No tool needed: LLM answered directly ─
    print(response.content)
    return           # ← exit here, skip all tool-call code

# ─ Tool needed: continue with steps ③-⑥ ─
# ... rest of tool call code ...
Section 09

Multi-Tool Loop Enhancement

The LLM may suggest calling multiple tools simultaneously. For example: "What is 3×4 AND 8+9?" could trigger two tool calls at once. Without a loop, only the first call would execute.

# Enhanced: loop over ALL tool calls from the LLM response

if not response.tool_calls:
    print(response.content)
    return

tool_messages = []  # collect results from all tool calls

for tool_call in response.tool_calls:  # ← loop (was: [0] only)
    selected_tool      = tool_call["name"]
    selected_tool_args = tool_call["args"]
    selected_tool_id   = tool_call["id"]

    tool_result = await named_tools[selected_tool].ainvoke(selected_tool_args)

    tool_messages.append(
        ToolMessage(content=str(tool_result), tool_call_id=selected_tool_id)
    )

# Pass ALL tool results back to LLM at once
final_response = await llm_with_tools.ainvoke(
    [prompt, response, *tool_messages]  # unpack all tool messages
)
print(final_response.content)

Section 12

Client 2 — Streamlit GUI Chatbot

The final version wraps all logic in a Streamlit GUI. The MCP core logic is identical to client1.py — only the input/output changes from terminal to a browser chat interface.

# client2.py — Streamlit chatbot (key structure)
import asyncio, streamlit as st
from langchain_mcp_adapters.client import MultiServerMCPClient
from langchain_openai import ChatOpenAI
from langchain_core.messages import ToolMessage

# ── Same servers dict ─────────────────────────────────────────────────
servers = { "math": {...}, "expense": {...}, "manim": {...} }

async def get_tools_and_llm():
    client = MultiServerMCPClient(servers=servers)
    tools = await client.get_tools()
    named_tools = {t.name: t for t in tools}
    llm_with_tools = ChatOpenAI(model="gpt-4").bind_tools(tools)
    return named_tools, llm_with_tools

async def chat(prompt, named_tools, llm_with_tools):
    response = await llm_with_tools.ainvoke(prompt)
    if not response.tool_calls:
        return response.content
    tool_messages = []
    for tc in response.tool_calls:
        result = await named_tools[tc["name"]].ainvoke(tc["args"])
        tool_messages.append(ToolMessage(str(result), tool_call_id=tc["id"]))
    final = await llm_with_tools.ainvoke([prompt, response, *tool_messages])
    return final.content

# ── Streamlit UI ──────────────────────────────────────────────────────
st.title("🤖 MCP Chatbot")
if "msgs" not in st.session_state: st.session_state.msgs = []
for m in st.session_state.msgs:
    st.chat_message(m["role"]).write(m["content"])
if user_in := st.chat_input("Ask anything..."):
    st.session_state.msgs.append({"role":"user","content":user_in})
    st.chat_message("user").write(user_in)
    nt, llm = asyncio.run(get_tools_and_llm())
    answer = asyncio.run(chat(user_in, nt, llm))
    st.session_state.msgs.append({"role":"assistant","content":answer})
    st.chat_message("assistant").write(answer)
# Run the chatbot
$ streamlit run client2.py
# Opens at http://localhost:8501

# 2. "What is the remainder of 2314 divided by 23?"
#    → modulo (local Math server) → 13 ✓
