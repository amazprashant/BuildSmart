Section 02

MCP Library Ecosystem — The Full Chronological Story

About 5 minutes are spent clarifying a common confusion: why do two different libraries exist for building MCP servers? Here's the complete story in order.

Late 2023 — MCP Protocol released by Anthropic
Developers want to build their own servers and clients. Problem: implementing all the MCP protocol rules from scratch in Python is extremely complex AND redundant (same boilerplate repeated for every server).
Anthropic releases the official MCP Python SDK
The mcp package on PyPI. Contains three sub-libraries: mcp.server (build servers), mcp.client (build clients), mcp.cli (command-line tools). Install: pip install mcp[cli]. Problem: very verbose — simple servers require huge amounts of boilerplate code.
Jeremiah Lowin (CEO of Prefect) creates fastmcp 1.0
He identified the boilerplate problem and built an abstraction layer on top of the MCP SDK. fastmcp makes building servers dramatically simpler — same functionality, 10x less code. It becomes extremely popular. Anthropic eventually adopts it: mcp.server.fastmcp gets built into the official SDK.
2025 — fastmcp goes independent as fastmcp 2.0
fastmcp's creator realizes there's so much more potential beyond the MCP spec. The official SDK focuses strictly on the spec. They diverge: pip install fastmcp now installs the independent fastmcp 2.0 (more features), while pip install mcp[cli] still includes fastmcp 1.0 inside the SDK. Today you can use either — but fastmcp 2.0 is recommended.
Bottom line: Why you see similar-looking code in different videos using different library names — both use fastmcp syntax under the hood. The difference is which package they installed: mcp[cli] (includes fastmcp 1.0) vs fastmcp (standalone version 2.0).
Section 03

MCP SDK vs fastmcp — Side-by-Side Code Comparison

The best way to understand why fastmcp won is to see the same server written both ways. Both do identical things — add two numbers:

MCP SDK (verbose — old way)

import asyncio
from mcp import Server
from mcp.server.stdio import stdio_server
from mcp.types import Tool, TextContent

# Create server instance
app = Server("demo-server")

# Register a tool — lots of ceremony
@app.list_tools()
async def list_tools():
    return [
        Tool(name="add",
             description="Add two numbers",
             inputSchema={
                 "type": "object",
                 "properties": {
                     "a": {"type": "number"},
                     "b": {"type": "number"}
                 },
                 "required": ["a", "b"]
             })
    ]

@app.call_tool()
async def call_tool(name, arguments):
    if name == "add":
        result = arguments["a"] + arguments["b"]
        return [TextContent(type="text", text=str(result))]

# Must manually configure transport!
async def main():
    async with stdio_server() as (r, w):
        await app.run(r, w, app.create_initialization_options())

asyncio.run(main())

~30 lines for a simple add function. Transport manually configured. Schema written by hand. Not beginner-friendly.

fastmcp 2.0 (simple — new way)

from fastmcp import FastMCP

# Create server — one line
mcp = FastMCP("demo-server")

# Just write a Python function
# and add ONE decorator
@mcp.tool()
def add(a: int, b: int) -> int:
    """Add two numbers together."""
    return a + b

# Run the server
if __name__ == "__main__":
    mcp.run()

# That's it! Transport is automatic.
# Schema is inferred from type hints.
# Description from docstring.

~10 lines for the same server. Transport auto-configured. Schema inferred from Python type hints. Description from docstring.

Demo Server Setup — Installing uv + fastmcp

Before writing any server code, you need to set up the development environment. fastmcp recommends uv — a blazingly fast Python package manager (much faster than pip).

Complete Setup Steps

01
Install uv (the fast Python package manager)

fastmcp recommends uv for project management. Install it via pip if you don't have it yet.

02
Create a new project folder

Create an empty folder anywhere on your machine (e.g. Desktop). Name it something descriptive like expense-tracker-mcp-server. Open it in VS Code.

03
Initialize uv in the project folder

Run uv init . (dot = current directory). This generates essential project files including main.py — where you'll write your server code.

04
Install fastmcp into the project

Run uv add fastmcp. This installs fastmcp 2.0 and all its dependencies into the project's virtual environment.

05
Verify installation

Run fastmcp version to confirm it's installed. You'll see: fastmcp version (2.x.x), MCP SDK version, Python version, platform (Mac/Windows), and the root path.

Section 06

Writing a Basic MCP Server with fastmcp

Now let's understand the anatomy of an MCP server. The demo server has just two tools: roll a dice and add two numbers. Simple — but it teaches the entire server-building pattern.

// Anatomy of a fastmcp server — four key elements

Complete Demo Server Code

from fastmcp import FastMCP   # Step 1: Import
import random

# Step 2: Create server instance with a name
mcp = FastMCP("demo-server")

# ─────────────────────────────────────────────────────────
# Step 3: Add tools using the @mcp.tool() decorator
# 
# Key: Write a NORMAL Python function.
# Add @mcp.tool() above it.
# That's it — it becomes an MCP Tool!
#
# fastmcp automatically:
#   • Reads type hints to build the JSON schema
#   • Uses the docstring as the tool description
#   • Handles all MCP protocol communication
# ─────────────────────────────────────────────────────────

@mcp.tool()
def roll_dice(num_dice: int) -> list[int]:
    """Roll a specified number of dice and return results (1–6 each)."""
    return [random.randint(1, 6) for _ in range(num_dice)]

@mcp.tool()
def add_numbers(a: int, b: int) -> int:
    """Add two numbers together and return their sum."""
    return a + b

# Step 4: Run the server (stdio transport is automatic)
if __name__ == "__main__":
    mcp.run()

# What the decorator does automatically:
#   • Registers the function as an MCP tool
#   • Sets tool name = function name
#   • Sets tool description = docstring
#   • Builds inputSchema from type annotations
#   • Handles JSON-RPC tools/list and tools/call
Key insight — the @mcp.tool() decorator: You write a completely normal Python function with type hints and a docstring. Adding @mcp.tool() transforms it into a full MCP Tool. No JSON schemas to write manually, no protocol handling — fastmcp does it all.

MCP Inspector — Testing Your Server

Before integrating your server with Claude Desktop, use the MCP Inspector to test it. This is a browser-based debugging tool that comes bundled with fastmcp — like Postman but for MCP servers.

🔬

What is MCP Inspector?

A browser-based debugging tool for MCP servers. Created by Anthropic and bundled with fastmcp. Shows all JSON-RPC message exchanges. Lets you manually call tools, list resources, test prompts — without needing Claude Desktop.

🏄

How to launch it

Run: uv run fastmcp dev main.py
This starts your server AND opens the MCP Inspector in your browser. The Inspector connects to your server automatically.

What You Can Do in MCP Inspector

List Tools

Click "List Tools" to fire a tools/list JSON-RPC request. See all registered tools with their schemas.

Call Tools

Select a tool, fill in arguments, click "Run Tool". See the JSON-RPC request/response in the History panel.

Message History

Every JSON-RPC message (initialize, tools/list, tools/call, etc.) shown in real-time. See the exact protocol communication.

Ping & Debug

Send ping requests, test sampling, test elicitation. All the protocol features from the Lifecycle video visible here.

Section 08

Integrating Your Server with Claude Desktop

Once your server works in MCP Inspector, you have two ways to connect it to Claude Desktop. The easiest way is the install command.

Method 1 — Install Command (Recommended)

One command installs the server directly into Claude Desktop's config automatically:

$ uv run fastmcp install claude-desktop main.py

# Optional: give it a custom name
$ uv run fastmcp install claude-desktop main.py --name "My Server"

# Optional: add environment variables
$ uv run fastmcp install claude-desktop main.py --env API_KEY=abc

Method 2 — Manual JSON Config

Settings → Developer → Edit Config → add to mcpServers:

{
  "mcpServers": {
    "my-server": {
      "command": "/absolute/path/to/uv",
      "args": [
        "run",
        "fastmcp",
        "run",
        "/absolute/path/to/main.py"
      ]
    }
  }
}
Common issue — absolute paths: After running the install command, Claude Desktop may fail to connect. The reason: the config file writes just uv as the command, but Claude Desktop can't find it without the full path. Fix: run which uv (Mac/Linux) or where uv (Windows) to get the absolute path. Edit the config file and replace uv with the full path like /usr/local/bin/uv. Save → close → restart Claude Desktop.

CREATE TABLE IF NOT EXISTS expenses (

    category    TEXT NOT NULL,      -- e.g., "Travel", "Food", "Health"

);

Tool 2: list_expenses — return ALL transactions from the database.

Date-Range Filtering

Iteration 1
add_expense + list_expenses
Two tools: write to DB + read from DB
from fastmcp import FastMCP
import sqlite3
from pathlib import Path

mcp = FastMCP("expense-tracker")

# Database file lives in the project folder
DB_PATH = Path(__file__).parent / "expenses.db"

def init_db():
    """Create the expenses table if it doesn't exist."""
    conn = sqlite3.connect(DB_PATH)
    conn.execute("""
        CREATE TABLE IF NOT EXISTS expenses (
            id          INTEGER PRIMARY KEY AUTOINCREMENT,
            date        TEXT NOT NULL,
            amount      REAL NOT NULL,
            category    TEXT NOT NULL,
            subcategory TEXT,
            note        TEXT
        )
    """)
    conn.commit()
    conn.close()

# Initialize DB when server starts
init_db()

@mcp.tool()
def add_expense(date: str, amount: float, category: str,
                subcategory: str = "", note: str = "") -> str:
    """Add a new expense entry to the database.
    
    Date format: YYYY-MM-DD. Category examples: Travel, Food,
    Health, Entertainment. Subcategory is optional.
    """
    conn = sqlite3.connect(DB_PATH)
    conn.execute(
        "INSERT INTO expenses (date, amount, category, subcategory, note)"
        " VALUES (?, ?, ?, ?, ?)",
        (date, amount, category, subcategory, note)
    )
    conn.commit()
    conn.close()
    return f"✓ Added: {category} expense of ₹{amount} on {date}"

@mcp.tool()
def list_expenses() -> list[dict]:
    """List all expense entries from the database in ascending date order."""
    conn = sqlite3.connect(DB_PATH)
    cursor = conn.execute(
        "SELECT id, date, amount, category, subcategory, note"
        " FROM expenses ORDER BY date ASC"
    )
    expenses = [
        {"id": r[0], "date": r[1], "amount": r[2],
         "category": r[3], "subcategory": r[4], "note": r[5]}
        for r in cursor.fetchall()
    ]
    conn.close()
    return expenses

if __name__ == "__main__":
    mcp.run()

Iteration 2
Date-Range Filtering for list_expenses
Add start_date + end_date parameters

Problem: listing ALL expenses becomes useless as the database grows. Solution: add optional date range parameters so Claude can filter by period.

# Updated list_expenses — now accepts a date range
@mcp.tool()
def list_expenses(start_date: str, end_date: str) -> list[dict]:
    """List expenses within a date range (inclusive).
    
    Both dates in YYYY-MM-DD format.
    Claude will auto-compute dates from natural language like
    'September', 'last week', 'last month'.
    """
    conn = sqlite3.connect(DB_PATH)
    cursor = conn.execute(
        "SELECT id, date, amount, category, subcategory, note"
        " FROM expenses"
        " WHERE date BETWEEN ? AND ?"    # ← The key change
        " ORDER BY date ASC",
        (start_date, end_date)
    )
    expenses = [
        {"id": r[0], "date": r[1], "amount": r[2],
         "category": r[3], "subcategory": r[4], "note": r[5]}
        for r in cursor.fetchall()
    ]
    conn.close()
    return expenses
The LLM magic: You say "show me expenses from September first week" — Claude's LLM auto-converts this to start_date="2025-09-01" and end_date="2025-09-07" before calling the tool. The tool just receives clean date strings. This is the power of connecting LLMs to tools.

Iteration 3
summarize — Total Spend by Category
New tool: GROUP BY SQL query
@mcp.tool()
def summarize(start_date: str, end_date: str,
              category: str | None = None) -> list[dict]:
    """Summarize total expenses by category within a date range.
    
    If category is provided: returns total for that category only.
    If category is None: returns totals for ALL categories.
    Date format: YYYY-MM-DD.
    """
    conn = sqlite3.connect(DB_PATH)

    # Build the base query dynamically
    query = "SELECT category, SUM(amount) AS total"
    query += " FROM expenses WHERE date BETWEEN ? AND ?"
    params = [start_date, end_date]

    if category:
        query += " AND category = ?"   # Filter by specific category
        params.append(category)

    query += " GROUP BY category ORDER BY category ASC"

    cursor = conn.execute(query, params)
    results = [
        {"category": row[0], "total": row[1]}
        for row in cursor.fetchall()
    ]
    conn.close()
    return results

Iteration 4
Adding a Resource — Category JSON File
Using @mcp.resource() instead of @mcp.tool()

The Problem This Solves

When Claude automatically determines the category for an expense, it may use inconsistent naming: one day "Education", next day "Upskilling" or "education" (lowercase). This creates messy data that's hard to analyze later.

Solution: Add a categories.json file as a Resource in your MCP server. Claude reads this resource to know exactly which category and subcategory names are valid — and always picks from that list.

categories.json Structure

// categories.json — stored in project folder
{
  "Food": ["Groceries", "Restaurant", "Delivery", "Snacks"],
  "Travel": ["Cab Ride", "Auto Rickshaw", "Flight", "Train", "Metro"],
  "Health": ["Medicine", "Doctor Consultation", "Gym", "Lab Tests"],
  "Entertainment": ["OTT Subscription", "Movies", "Games", "Sports"],
  "Education": ["Online Course", "Books", "Subscription", "Workshop"],
  "Shopping": ["Clothing", "Electronics", "Home Essentials", "Gifts"],
  "Utilities": ["Electricity", "Internet", "Mobile Recharge", "Water"],
  "Housing": ["Rent", "Maintenance", "Repairs"]
}

Adding the Resource to Your MCP Server

# Add this to main.py alongside the tools

import json
CATEGORIES_PATH = Path(__file__).parent / "categories.json"

@mcp.resource("categories://expense-categories")
def get_categories() -> str:
    """Returns all valid expense categories and their subcategories.
    
    Always reference this resource when adding a new expense to ensure
    consistent category and subcategory naming in the database.
    """
    with open(CATEGORIES_PATH) as f:
        return json.load(f)

# Key difference: @mcp.resource() vs @mcp.tool()
#
# @mcp.tool()     → Dynamic action, executed on demand
#                   Changes data, makes calculations
#
# @mcp.resource() → Static data, read-only
#                   Returns pre-existing information
#                   Claude can "attach" it to a conversation

How Claude Uses the Resource

Attach to Conversation

In Claude Desktop, click the "+" icon → "Add from Expense Tracker" → "categories". The full JSON contents are now attached to the conversation as context.

Consistent Categories

When adding a new expense, tell Claude: "Fetch category from the pasted resource." Claude reads the JSON and picks the exact right category and subcategory — no more inconsistency.

Resources vs Tools: A Resource is like a file the AI can read. A Tool is like a function the AI can execute. Use Resources for static data (categories, configuration, templates). Use Tools for dynamic operations (add/query/update the database).
Section 14

Bonus: Convert FastAPI App → fastmcp Server in 3 Lines

One of fastmcp 2.0's most powerful features: if you already have a FastAPI backend, you can instantly create an MCP server from it without rewriting any code.

// Business scenario: Company already has FastAPI backend → wants to add MCP support

The 3-Line Conversion

# server.py — this is ALL you need to create a fastmcp server
#             from your existing FastAPI app

from fastmcp import FastMCP
from main import app  # Your existing FastAPI app object

# ONE LINE creates the entire MCP server from your FastAPI app
mcp = FastMCP.from_fastapi(app, name="expense-tracker-mcp")

if __name__ == "__main__":
    mcp.run()

# fastmcp automatically:
#   • Converts each FastAPI endpoint into an MCP Tool
#   • Reads Pydantic models for input validation
#   • Copies endpoint descriptions as tool descriptions
#   • Handles all MCP protocol communication
# You write ZERO additional tool code!

FastAPI endpoint → MCP Tool mapping

POST /expenses → add_expense tool
GET /expenses → get_expenses tool
GET /expenses/summary → get_expense_summary tool

Endpoint names, parameters, types, and Pydantic validation are all preserved automatically.

Business value of this feature

A company with an existing FastAPI backend can expose their entire product as an MCP server in minutes — not days. Adds Claude Desktop as a new platform without any separate server development. Reduces development time dramatically.

Design philosophy connection: fastmcp was built with the same design principles as FastAPI. The creator of fastmcp studied FastAPI's approach (decorator-based, type-hint-driven, Pydantic integration) and applied the same ideas to MCP. That's why they're so compatible — and why converting between them is so seamless.
