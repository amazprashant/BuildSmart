5 3-Phase Workflow

The 3-Phase Newsletter Creation Process

The entire newsletter creation is broken into 3 distinct phases, each triggered by a single detailed prompt given to Claude. The AI handles all tool calls autonomously.

1
Phase 1 — Research

Read Google Drive: Fetch "Content Ideas" file (list of potential newsletter topics) and "Performance Data" file (past newsletter open rates, click rates, read times).

Read Gmail Feedback: Scan inbox for subscriber feedback emails to understand audience preferences for this edition.

Decide Research Topics: Based on all 3 inputs (content ideas + performance data + feedback), Claude decides what to research for this week.

Web Search: Find the week's biggest AI news story and 3–5 quick updates. Saves as web_research.md

arXiv Search: Find trending research papers with summaries and download links. Saves as arxiv_research.md

GitHub Search: Find top trending AI repositories with star counts and descriptions. Saves as github_research.md

Product Hunt Search: Find top AI products launched this week. Saves as producthunt_research.md

Twitter/X Search: Fetch top tweets from leading AI personalities. Saves as twitter_research.md

Output: 5 markdown files saved to a local folder on desktop — one per source.

2
Phase 2 — Editing (Draft Assembly)

Read all 5 research files from the local desktop folder created in Phase 1.

Read Sample Newsletter Template from Google Drive — a pre-built document showing the exact 9-section structure and writing style expected.

Assemble Final Draft: Populate each of the 9 sections with the relevant research data. Ensure smooth transitions, clear section headers, and an engaging editorial tone.

Output: A single final_draft.md saved to the same local folder.

3
Phase 3 — Design (HTML Generation)

Read Final Draft: Fetch the final_draft.md from local storage.

Apply Design Spec: Claude receives layout specifications — visual structure, typography, color scheme, responsive behaviour — as part of the prompt.

Generate HTML Email: Produces a production-ready HTML email compatible across major email clients (Gmail, Outlook, Apple Mail).

Generate Plain Text Fallback: Also produces a plain text version for email clients that block HTML or mark HTML emails as spam.

Output: newsletter.html + newsletter.txt saved to output folder. Ready to paste into Mailchimp or any email sending tool.

9 MCP Configuration

Zero Custom Code — Just JSON Configuration

One of the most powerful demonstrations in the video: despite integrating 8+ external tools, zero custom function calls or API wrappers were written. All integration is handled through a single JSON config file.

// claude_desktop_config.json — MCP Server Configuration
{
  "mcpServers": {
    "web-search": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-brave-search"],
      "env": { "BRAVE_API_KEY": "your_key_here" }
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "your_token_here" }
    },
    "arxiv": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-arxiv"]
    },
    "google-drive": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-gdrive"]
    },
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem",
               "/Users/your-name/Desktop"]
    }
    // ... more servers for Gmail, Twitter, Product Hunt, Notion
  }
}
Key Insight: You only provide the configuration. You never write the tool's internal logic. If the GitHub MCP server is updated with new features or bug fixes, you don't need to change a single line of your config — the server handles itself. This is the power of the MCP protocol.

Add the Config

Write a JSON entry in claude_desktop_config.json for each MCP server you want to add. Typically 4–8 lines per tool.

Claude Handles the Rest

Claude automatically discovers the tool's capabilities, makes the appropriate API calls, and returns structured results — no glue code needed.

Updates Are Seamless

When an MCP server releases updates, your config stays the same. The server-side handles all changes. Zero maintenance burden on your side.

10 Key Takeaways

What MCP Enables

The core lesson from the trailer video, summarised as actionable insights:

⚡

AI + Tools = Exponential Capability

A standalone LLM is powerful but limited to its training data. Connect it to real-time tools via MCP and it becomes an autonomous agent capable of executing complex multi-step workflows.

🔧

3 Prompts to a Finished Product

The entire newsletter — research, writing, and HTML design — is completed with just 3 carefully crafted prompts. Prompt engineering replaces traditional coding for many tasks.

🔌

Standardised Integration Protocol

MCP provides a universal standard for AI-tool communication. Any MCP-compatible tool can be plugged in to any MCP-compatible AI — similar to how USB standardised device connections.

📈

Feedback Loop for Improvement

By incorporating Gmail feedback and performance data, the system learns from every edition. Over time, the newsletter auto-optimises for what the audience actually reads.

🧩

Composable Architecture

Each phase (Research, Editing, Design) is independent and swappable. You can replace any phase's tools, swap the AI model, or change the output format without rebuilding everything.

⏱️

Time Investment: Config Only

Total custom code: one JSON configuration file. All business logic is handled by Claude's intelligence and the MCP servers. Build once, run indefinitely.
