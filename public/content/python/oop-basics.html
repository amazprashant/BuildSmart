Class — The Blueprint

A Class is a blueprint that defines what data an object will have and what it can do. The class itself does nothing until you create objects from it.

class Student:        # class names start with a Capital letter
    pass
📐

Class = Blueprint

Like an architect's plan — defines the structure, builds nothing itself.

🏠

Object = Instance

The actual thing built from the blueprint.

Object & Instantiation

class Student:
    name = 'Karan'      # class-level attribute

s1 = Student()           # s1 is an object/instance of Student
s2 = Student()            # s2 is a separate, independent object

print(s1.name)             # Karan
Note: "Object" and "instance" mean the same thing. Creating an object from a class is called instantiation.

The Constructor — __init__

__init__ runs automatically every time an object is created. It sets up the object's initial data.

class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

s1 = Student('Karan', 97)    # __init__ runs automatically
print(s1.name)                 # Karan
Watch out: If you define two __init__ methods in one class, Python only keeps the last one — there's no constructor overloading like in Java/C++.

The self Parameter

self refers to the current object — the specific instance being created or used. It's not a keyword, just a universal convention.

class Student:
    def __init__(self, name):
        self.name = name    # store name IN this specific object

s1 = Student('Karan')
# self inside __init__ IS s1 — same object, same memory address

Instance vs Class Attributes

class Student:
    college_name = 'ABC College'    # CLASS attribute — shared by ALL objects

    def __init__(self, name, marks):
        self.name = name              # INSTANCE attribute — unique per object
        self.marks = marks

s1 = Student('Karan', 97)
s2 = Student('Arjun', 88)

print(s1.college_name, s2.college_name)   # ABC College, ABC College (shared)
print(s1.name, s2.name)                     # Karan, Arjun (independent)

Methods

class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

    def welcome(self):              # always takes self first
        print('Welcome student:', self.name)

    def get_marks(self):
        return self.marks

s1 = Student('Karan', 97)
s1.welcome()              # Welcome student: Karan
print(s1.get_marks())      # 97

Static Methods

Static methods don't take self and can't access object data — they're utility functions that just live inside a class for organization.

class Student:
    @staticmethod
    def hello():
        print('Hello from Student class!')

Student.hello()     # call via class name — preferred

Abstraction

class Car:
    def __init__(self):
        self.acc = False
        self.clutch = False

    def start(self):           # user only sees THIS method
        self.clutch = True     # internal steps — HIDDEN from the user
        self.acc = True
        print('Car Started!')

car1 = Car()
car1.start()    # user never sees clutch/acc being set internally

Encapsulation

Core idea: A class is a "capsule" wrapping data (attributes) together with the methods that operate on that data — into one single unit. Every class you write practices encapsulation by definition.

Chapter Summary

  • Programming evolved: Procedural → Functional → Object-Oriented
  • A Class is a blueprint; an Object (instance) is the actual entity built from it
  • __init__ runs automatically on object creation to set up initial data
  • self refers to the current object — always the first parameter of any method
  • Instance attributes are unique per object; class attributes are shared by all objects
  • Static methods (@staticmethod) skip self entirely — class-level utilities
  • Abstraction hides implementation details; Encapsulation bundles data + methods together
