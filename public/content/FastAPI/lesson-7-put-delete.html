PUT vs PATCH

PUT — Full Replace

  • Replaces the entire resource
  • All fields must be provided
  • Missing fields → null / default
  • Idempotent (safe to retry)

PATCH — Partial Update

  • Updates specific fields only
  • Only send changed fields
  • Missing fields stay unchanged
  • Not idempotent in general
2

PUT — Full Update

from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
from typing import Dict

app = FastAPI()

class Item(BaseModel):
    name: str
    price: float
    in_stock: bool = True

items: Dict[int, Item] = {1: Item(name="Pen", price=10.0)}

@app.put("/items/{item_id}")
def replace_item(item_id: int, item: Item):
    if item_id not in items:
        raise HTTPException(status_code=404, detail="Item not found")
    items[item_id] = item  # completely replace
    return {"id": item_id, **item.model_dump()}

# PUT /items/1 with body {"name": "Pen Pro", "price": 25.0}
# → in_stock defaults to True since not provided

PATCH — Partial Update

class ItemUpdate(BaseModel):
    name: str | None = None    # all fields optional for PATCH
    price: float | None = None
    in_stock: bool | None = None

@app.patch("/items/{item_id}")
def partial_update(item_id: int, update: ItemUpdate):
    if item_id not in items:
        raise HTTPException(status_code=404, detail="Item not found")

    existing = items[item_id]
    update_data = update.model_dump(exclude_unset=True)  # only sent fields
    updated = existing.model_copy(update=update_data)
    items[item_id] = updated
    return {"id": item_id, **updated.model_dump()}

# PATCH /items/1 with body {"price": 30.0}
# → name and in_stock unchanged, only price updated ✅
model_copy(update=...) pattern

model_copy(update=data) creates a new Pydantic model instance with specific fields overridden. Combined with exclude_unset=True, this is the standard FastAPI pattern for safe partial updates.

DELETE — Remove Resources

from fastapi import Response

@app.delete("/items/{item_id}", status_code=204)
def delete_item(item_id: int):
    if item_id not in items:
        raise HTTPException(status_code=404, detail="Item not found")
    del items[item_id]
    # status 204 = no body returned

# Alternative: return a confirmation message (use status 200)
@app.delete("/items/{item_id}")
def delete_item_with_message(item_id: int):
    if item_id not in items:
        raise HTTPException(status_code=404, detail="Item not found")
    deleted = items.pop(item_id)
    return {"message": f"Deleted: {deleted.name}"}
204 No Content cannot have a body

If you declare status_code=204, FastAPI strips the response body automatically. If you want to return a message about what was deleted, use status_code=200 instead.

Complete CRUD with Router

router = APIRouter(prefix="/products", tags=["products"])

Use APIRouter to organize routes

As your API grows, use APIRouter to split routes into separate files. The prefix applies to all routes in the router, and tags groups them in the auto-generated docs.
