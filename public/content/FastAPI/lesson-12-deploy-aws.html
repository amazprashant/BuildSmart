Option A — EC2 (Direct Docker)

  • 1

    Launch EC2 Instance

    Choose Ubuntu 22.04, t2.micro (free tier), add Security Group inbound rule: port 8000 from 0.0.0.0/0.

  • 2

    SSH & Install Docker

    ssh -i key.pem ubuntu@<ip> then sudo apt update && sudo apt install docker.io -y

  • 3

    Clone & Run

    git clone <repo> && cd <repo> && sudo docker build -t myapp . && sudo docker run -d -p 8000:8000 myapp

# Access your API at:
http://<EC2-PUBLIC-IP>:8000
http://<EC2-PUBLIC-IP>:8000/docs  # Swagger UI
3

Option B — ECR + ECS Fargate

Step 1: Push image to ECR (Elastic Container Registry)

# Authenticate Docker to ECR
aws ecr get-login-password --region ap-south-1 | \
  docker login --username AWS --password-stdin \
  <ACCOUNT_ID>.dkr.ecr.ap-south-1.amazonaws.com

# Create ECR repository
aws ecr create-repository --repository-name my-fastapi

# Build, tag, and push
docker build -t my-fastapi .
docker tag my-fastapi:latest \
  <ACCOUNT_ID>.dkr.ecr.ap-south-1.amazonaws.com/my-fastapi:latest
docker push \
  <ACCOUNT_ID>.dkr.ecr.ap-south-1.amazonaws.com/my-fastapi:latest

Step 2: Create ECS Cluster & Service

# Via AWS Console or CLI:
# 1. Create ECS Cluster (Fargate)
# 2. Create Task Definition — reference your ECR image URL
#    Set CPU: 256, Memory: 512
#    Container port: 8000
# 3. Create Service — attach to a VPC, public subnet
# 4. Add ALB (Application Load Balancer) for production traffic
ECS Fargate = serverless containers

Fargate runs your containers without you managing any EC2 instances. AWS automatically provisions, scales, and patches the underlying infrastructure. You only pay per CPU/memory second your tasks run.

4

Option C — AWS App Runner (Easiest)

# App Runner — deploy directly from ECR image
# 1. AWS Console → App Runner → Create Service
# 2. Source: Container registry → ECR → select your image
# 3. Port: 8000
# 4. CPU: 1 vCPU, Memory: 2GB
# 5. Auto-deploy: On (redeploys when ECR image updates)
# 6. Create → get a public URL in ~2 minutes

# App Runner automatically:
# ✅ Provisions infrastructure
# ✅ Handles TLS/HTTPS
# ✅ Auto-scales from 0 to N
# ✅ Health checks & restarts
App Runner cold starts

App Runner can scale to zero when idle, causing cold starts on the first request. For APIs with consistent traffic, keep min instances at 1. For occasional use, the cost savings outweigh the ~2s cold start delay.

Environment Variables on AWS

# EC2: pass at docker run time
docker run -d -p 8000:8000 \
  -e DATABASE_URL="postgresql://..." \
  -e SECRET_KEY="$(aws ssm get-parameter --name /myapp/secret --with-decryption --query 'Parameter.Value' --output text)" \
  myapp

# ECS: add environment variables in Task Definition
# App Runner: add in "Environment variables" section in console

# Best practice: use AWS SSM Parameter Store or Secrets Manager
# for sensitive values — never hardcode them in task definitions
AWS deployment comparison

Start with App Runner for simplicity. Move to ECS Fargate when you need VPC networking, multiple services, or more control. Use EC2 only if you need custom GPU instances, specific OS config, or have existing infrastructure.
