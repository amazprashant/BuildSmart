Your FunctionPython object ready

When a function parameter type is a Pydantic BaseModel, FastAPI automatically reads the request body as JSON and validates it. No manual JSON parsing needed.

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None

@app.post("/items")
def create_item(item: Item):
    return item  # Pydantic model serializes to JSON automatically

# Request body (JSON):
# {
#   "name": "Laptop",
#   "price": 49999.0,
#   "description": "Gaming laptop",
#   "tax": 4999.9
# }

Status Codes

from fastapi import status

@app.post("/items", status_code=status.HTTP_201_CREATED)
def create_item(item: Item):
    return item

@app.delete("/items/{id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_item(id: int):
    return None  # 204 sends no body

Mixing Path + Query + Body

@app.put("/users/{user_id}/items/{item_id}")
def update_item(
    user_id: int,          # path param
    item_id: int,          # path param
    q: str | None = None,  # query param
    item: Item = None      # request body (Pydantic model)
):
    result = {"user_id": user_id, "item_id": item_id}
    if q:
        result["query"] = q
    if item:
        result["item"] = item
    return result

# FastAPI knows the difference:
# • Path params  → declared in @app.xxx("/route/{param}")
# • Query params → simple types (str/int/bool) not in path
# • Body         → Pydantic BaseModel subclass

Response Model

class UserCreate(BaseModel):
    name: str
    email: str
    password: str  # ← accept password in input...

class UserResponse(BaseModel):
    id: int
    name: str
    email: str
    # No password field! ← don't return it

@app.post(
    "/users",
    response_model=UserResponse,    # ← filters output to this shape
    status_code=201
)
def create_user(user: UserCreate):
    # Imagine saving to DB and getting back an id
    return {"id": 1, "name": user.name, "email": user.email, "password": user.password}
    # FastAPI strips 'password' from response automatically ✅
Input vs Output models

Use separate Pydantic models for input (what you accept) and output (what you return). This pattern ensures sensitive fields like passwords and internal IDs never leak into API responses, without any manual filtering.

Receiving a List in the Body

from typing import List

@app.post("/items/batch")
def create_many(items: List[Item]):
    return {"created": len(items), "items": items}

# Send array in JSON body:
# [
#   {"name": "Pen", "price": 10.0},
#   {"name": "Notebook", "price": 50.0}
# ]
Multiple body parameters

If you need multiple top-level body objects, use Body() from fastapi with embed=True or define a wrapper Pydantic model. FastAPI can only auto-detect one bare Pydantic model as the body at a time.
