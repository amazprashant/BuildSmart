Core Concepts

Docker Architecture
DockerfileRecipe / instructions
→ build →
ImageSnapshot (read-only)
→ run →
ContainerRunning instance
  • Dockerfile — text file with instructions to build an image
  • Image — immutable snapshot of your app + dependencies
  • Container — a running instance of an image
  • Registry — storage for images (Docker Hub, AWS ECR)
  • Volume — persistent storage that survives container restarts
The "works on my machine" problem — solved

Docker bundles your code, Python version, and all libraries into a single image. It runs identically on your laptop, a teammate's Mac, and a Linux AWS server — eliminating environment differences.

Writing a Dockerfile

# Each line creates a new "layer" in the image

# 1. Base image (official Python runtime)
FROM python:3.11-slim

# 2. Set working directory inside container
WORKDIR /app

# 3. Copy requirements first (for layer caching)
COPY requirements.txt .

# 4. Install dependencies
RUN pip install --no-cache-dir -r requirements.txt

# 5. Copy application code
COPY . .

# 6. Expose port (documentation only — doesn't publish)
EXPOSE 8000

# 7. Command to run when container starts
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
Why copy requirements.txt before your code?

Docker caches each layer. If your code changes but requirements.txt doesn't, the pip install layer is reused — making rebuilds much faster. If you copy everything at once, any code change triggers a full reinstall.

Essential Docker Commands

CommandWhat it Does
docker build -t myapp .Build image from Dockerfile in current directory, tag as "myapp"
docker run -p 8000:8000 myappRun container, map host port 8000 → container port 8000
docker run -d myappRun in detached (background) mode
docker psList running containers
docker ps -aList all containers (including stopped)
docker stop <id>Stop a running container
docker logs <id>View container output logs
docker exec -it <id> bashOpen interactive shell inside container
docker imagesList all local images
docker rmi myappRemove an image

# .dockerignore — prevent unnecessary files from being copied

*.pyc

.env

.gitignore
venv/
.venv/

Like .gitignore but for Docker builds. Excluding venv/ is critical — it can be hundreds of MB and you don't want it in the image (dependencies are installed fresh via pip).

Environment Variables

# Pass env vars at runtime
docker run -p 8000:8000 \
  -e DATABASE_URL=postgresql://... \
  -e SECRET_KEY=mysecret \
  myapp

# Or use a .env file
docker run -p 8000:8000 --env-file .env myapp

# In Dockerfile (with defaults)
ENV LOG_LEVEL=info
ENV WORKERS=1
Never bake secrets into images

Secrets embedded in a Dockerfile become part of the image layers. Anyone with access to the image can extract them. Always pass secrets at runtime via -e flags, --env-file, or secret management services.
