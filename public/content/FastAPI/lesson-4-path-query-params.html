Path — resource location
Path Parameter — dynamic segment
Query Key — filter/option name

2

Path Parameters

Path parameters are required dynamic parts of the URL path. Define them with {curly_braces} in the route and match the variable name in the function.

@app.get("/users/{user_id}")
def get_user(user_id: int):        # ← int type → auto validates & converts
    return {"user_id": user_id}

@app.get("/users/{user_id}/posts/{post_id}")
def get_post(user_id: int, post_id: int):
    return {"user_id": user_id, "post_id": post_id}

# /users/42      → {"user_id": 42}
# /users/abc     → 422 Unprocessable Entity (not an int!)
# /users/42/posts/7 → {"user_id": 42, "post_id": 7}

Enum Path Parameters

from enum import Enum

class ModelName(str, Enum):
    alexnet = "alexnet"
    resnet = "resnet"
    lenet = "lenet"

@app.get("/models/{model_name}")
def get_model(model_name: ModelName):
    return {"model": model_name, "message": f"You chose {model_name.value}"}

# /models/alexnet → valid ✅
# /models/unknown → 422 Unprocessable Entity ✅ (auto-validated)
Path parameter ordering matters

If you have /users/me and /users/{user_id}, put the static route first. FastAPI matches routes in order — /users/me would be captured as user_id="me" if the dynamic route is declared first.

3

Query Parameters

Query parameters come after ? in the URL. In FastAPI, any function parameter that's not a path parameter is treated as a query parameter.

@app.get("/items")
def list_items(
    skip: int = 0,           # optional with default 0
    limit: int = 10,         # optional with default 10
    search: str | None = None  # optional, can be None
):
    return {"skip": skip, "limit": limit, "search": search}

# GET /items                      → skip=0, limit=10, search=None
# GET /items?limit=5              → skip=0, limit=5, search=None
# GET /items?skip=20&search=shoe  → skip=20, limit=10, search="shoe"

Required Query Parameters

# No default value = required query parameter
@app.get("/search")
def search(q: str):  # ← required! No default.
    return {"query": q}

# GET /search        → 422 Error: field required
# GET /search?q=hat  → {"query": "hat"}
4

Combining Path + Query Params

@app.get("/users/{user_id}/items")
def get_user_items(
    user_id: int,           # ← path param
    skip: int = 0,          # ← query param
    limit: int = 10,        # ← query param
    active: bool = True     # ← query param (bool: "true"/"false"/"1"/"0")
):
    return {
        "user_id": user_id,
        "skip": skip,
        "limit": limit,
        "active": active
    }

# GET /users/42/items?skip=5&active=false
# → {"user_id": 42, "skip": 5, "limit": 10, "active": False}
Boolean query parameters

FastAPI accepts true, True, 1, on, yes as True, and false, False, 0, off, no as False for boolean query parameters.

Path vs Query — When to Use Each

UsePath ParamQuery Param
Identifying a specific resource✅ Best choice❌ Avoid
Filtering a list❌ Not suitable✅ Best choice
Required value✅ Always required✅ Can be required or optional
Optional value❌ Always present✅ Can have defaults
Example/users/42/users?role=admin
Rule of thumb

Path for identity (which specific resource), query for options (how to filter, sort, paginate). /products/123 → product 123. /products?category=shoes&sort=price → filtered product list.
