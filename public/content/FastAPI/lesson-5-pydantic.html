What is Pydantic?

Pydantic is a Python library that uses type hints to validate data. You define the shape of your data as a class, and Pydantic ensures incoming data matches — converting types where possible and raising clear errors when it doesn't.

BaseModel — Core Concept

from pydantic import BaseModel, EmailStr, Field
from typing import Optional, List
from datetime import datetime

class Address(BaseModel):
    street: str
    city: str
    country: str = "India"    # default value

class User(BaseModel):
    id: int
    name: str
    email: str
    age: int
    is_active: bool = True    # optional with default
    score: float | None = None  # optional, can be None
    tags: List[str] = []        # optional list, default empty
    address: Address            # nested model
    created_at: datetime = datetime.now()

# Usage
user = User(
    id=1,
    name="Alice",
    email="alice@example.com",
    age=28,
    address={"street": "MG Road", "city": "Mumbai"}  # auto-converts dict!
)

print(user.name)    # "Alice"
print(user.age)     # 28  (int)
print(user.address.city)  # "Mumbai"

Field — Constraints & Metadata

from pydantic import BaseModel, Field

class Product(BaseModel):
    name: str = Field(
        ...,                     # ... means required (no default)
        min_length=2,
        max_length=100,
        description="Product name"
    )
    price: float = Field(
        gt=0,                    # must be > 0
        lt=10000,                # must be < 10000
        description="Price in INR"
    )
    quantity: int = Field(ge=0, le=1000)  # 0 ≤ quantity ≤ 1000
    discount_percent: float = Field(default=0, ge=0, le=100)
    sku: str = Field(pattern=r'^[A-Z]{3}-\d{4}$')  # regex validation

# Field constraints:
# gt=  → greater than
# ge=  → greater than or equal
# lt=  → less than
# le=  → less than or equal
# min_length, max_length  → for strings
# pattern  → regex for strings

Type Coercion & Validation

class Item(BaseModel):
    count: int
    price: float
    active: bool

# Pydantic auto-converts compatible types:
item = Item(count="5", price="9.99", active="true")
print(item.count)   # 5     (string "5" → int 5)
print(item.price)   # 9.99  (string → float)
print(item.active)  # True  (string "true" → bool True)

# Invalid data raises ValidationError:
try:
    Item(count="abc", price=10, active=True)
except Exception as e:
    print(e)
# → 1 validation error: count: value is not a valid integer
FastAPI + Pydantic = automatic request validation

When you use a Pydantic model as a FastAPI function parameter, FastAPI automatically parses the request JSON, validates it, and returns a 422 Unprocessable Entity with clear error details if validation fails — all without any manual code.

Serialization

user = User(id=1, name="Alice", email="a@b.com", age=28, address={...})

# Convert to dict
user.model_dump()                           # all fields
user.model_dump(exclude={'id', 'email'})    # exclude fields
user.model_dump(include={'name', 'age'})    # include only
user.model_dump(exclude_unset=True)         # only set fields (for PATCH)
user.model_dump(exclude_none=True)          # exclude None values

# Convert to JSON string
user.model_dump_json()

# Create from dict
data = {"id": 2, "name": "Bob", ...}
user2 = User.model_validate(data)
exclude_unset=True for PATCH endpoints

When doing partial updates (PATCH), use exclude_unset=True to get only the fields the client explicitly sent — not the defaults. This prevents accidentally overwriting DB fields with defaults.
