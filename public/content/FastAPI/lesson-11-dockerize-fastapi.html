2

Production Dockerfile

# Dockerfile
FROM python:3.11-slim

# Prevents Python from writing .pyc files
ENV PYTHONDONTWRITEBYTECODE=1
# Prevents Python from buffering stdout/stderr (see logs immediately)
ENV PYTHONUNBUFFERED=1

WORKDIR /app

# Install dependencies (separate layer for caching)
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copy source code
COPY . .

# Create non-root user for security
RUN adduser --disabled-password --gecos '' appuser
USER appuser

EXPOSE 8000

# Use gunicorn with uvicorn workers for production
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000", "--workers", "2"]

requirements.txt

fastapi==0.111.0
uvicorn[standard]==0.30.0
pydantic==2.7.1
# Add your other dependencies here

docker-compose for Multi-Service Apps

# docker-compose.yml
version: "3.9"

services:
  api:
    build: .
    ports:
      - "8000:8000"
    environment:
      - DATABASE_URL=postgresql://user:password@db:5432/mydb
      - REDIS_URL=redis://redis:6379
    depends_on:
      - db
      - redis
    volumes:
      - .:/app      # mount code for hot reload in dev

  db:
    image: postgres:15-alpine
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
      POSTGRES_DB: mydb
    volumes:
      - pg_data:/var/lib/postgresql/data
    ports:
      - "5432:5432"

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"

volumes:
  pg_data:
4

Build & Run Workflow

# Build and start all services
docker-compose up --build

# Start in background
docker-compose up -d --build

# View logs
docker-compose logs -f api

# Stop all services
docker-compose down

# Stop and remove volumes (reset DB)
docker-compose down -v

# Run a one-off command (e.g. DB migrations)
docker-compose run api alembic upgrade head

# Rebuild just the API container
docker-compose up --build api

Dev vs Prod Configuration

# docker-compose.override.yml (auto-applied in dev)
version: "3.9"

services:
  api:
    command: uvicorn main:app --host 0.0.0.0 --port 8000 --reload
    volumes:
      - .:/app   # live reload on file changes
    environment:
      - DEBUG=true

# docker-compose.prod.yml (use explicitly in production)
# docker-compose -f docker-compose.yml -f docker-compose.prod.yml up
--reload only in development

The --reload flag watches for file changes and restarts the server. Never use it in production — it's slow, uses extra memory, and the file-watcher can cause security issues in containerized environments.

6

Service Communication in docker-compose

Container Networking
Browserlocalhost:8000
→
api container:8000
→
db containerdb:5432

Inside docker-compose, containers talk to each other using service names as hostnames. Your API connects to db:5432 (not localhost:5432) because db is the service name defined in docker-compose.yml.

depends_on is not enough

depends_on only waits for the container to start — not for the service inside (like Postgres) to be ready. In production, add a health check or a startup retry loop in your app so it reconnects if the DB isn't ready yet.
