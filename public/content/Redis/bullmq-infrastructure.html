BullMQ Queue Infrastructure

BullMQ is a production-grade queue library built on Redis. It provides retries, delays, concurrency control, rate limiting, and a dashboard — all with Redis as the backbone.

Why BullMQ over Raw Redis?

🔄

Automatic Retries

Retry failed jobs with configurable backoff (fixed, exponential).

⏰

Delayed Jobs

Schedule jobs to run in the future. Built-in with no extra code.

🔢

Concurrency

Run N workers in parallel. Rate limit per queue or per job type.

📊

Job Lifecycle

Track each job through wait → active → completed/failed states.

🖥️

Bull Board UI

Visual dashboard to monitor queues, inspect jobs, retry failures.

🔗

Job Dependencies

Chain jobs — start job B only after job A completes.

Core Concepts: Queue & Worker

import { Queue, Worker, Job } from 'bullmq';
import Redis from 'ioredis';

const connection = new Redis({ maxRetriesPerRequest: null });

// ── Queue (producer) ──
const emailQueue = new Queue('email', { connection });

await emailQueue.add('welcome-email', {
  to: 'user@example.com',
  name: 'Alice',
  template: 'welcome',
});

// Add with options
await emailQueue.add(
  'order-confirm',
  { orderId: 'ORD-123', to: 'bob@example.com' },
  {
    attempts: 3,                     // retry up to 3 times
    backoff: { type: 'exponential', delay: 2000 }, // 2s, 4s, 8s
    delay: 5000,                     // start after 5 seconds
    priority: 1,                     // lower number = higher priority
    removeOnComplete: 100,           // keep last 100 completed jobs
    removeOnFail: 50,                // keep last 50 failed jobs
  }
);

// ── Worker (consumer) ──
const worker = new Worker(
  'email',
  async (job: Job) => {
    console.log(`Processing job ${job.id}: ${job.name}`);
    const { to, template } = job.data;
    await sendEmail(to, template);
    return { sent: true, timestamp: Date.now() };
  },
  { connection, concurrency: 5 } // process up to 5 jobs simultaneously
);

worker.on('completed', (job, result) => {
  console.log(`Job ${job.id} completed:`, result);
});

worker.on('failed', (job, err) => {
  console.error(`Job ${job?.id} failed:`, err.message);
});

Job Lifecycle States

⏳ wait 🕐 delayed ▶ active ✓ completed ✗ failed 
// Check job state
const job = await emailQueue.getJob(jobId);
const state = await job?.getState(); // 'wait' | 'active' | 'completed' | 'failed' | 'delayed'

// Queue metrics
const counts = await emailQueue.getJobCounts('wait', 'active', 'completed', 'failed');
console.log(counts); // { wait: 5, active: 2, completed: 847, failed: 3 }

Repeatable Jobs (Cron)

// Run every day at 9am
await emailQueue.add(
  'daily-digest',
  { type: 'digest' },
  {
    repeat: { cron: '0 9 * * *' },
    removeOnComplete: 1,
  }
);

// Remove a repeatable job
const repeatableJobs = await emailQueue.getRepeatableJobs();
await emailQueue.removeRepeatableByKey(repeatableJobs[0].key);

Bull Board Dashboard

import { createBullBoard } from '@bull-board/api';
import { BullMQAdapter } from '@bull-board/api/bullMQAdapter';
import { ExpressAdapter } from '@bull-board/express';
import express from 'express';

const serverAdapter = new ExpressAdapter();
serverAdapter.setBasePath('/admin/queues');

createBullBoard({
  queues: [
    new BullMQAdapter(emailQueue),
    new BullMQAdapter(notificationsQueue),
  ],
  serverAdapter,
});

const app = express();
app.use('/admin/queues', serverAdapter.getRouter());
// Visit: http://localhost:3000/admin/queues
Tip:

Protect the dashboard with authentication middleware in production. The dashboard shows all job data, including payloads.

Multiple Queues Pattern

// Separate queues by priority or domain
const criticalQueue = new Queue('critical', { connection });
const emailQueue    = new Queue('email', { connection });
const reportsQueue  = new Queue('reports', { connection });

// High-concurrency for critical, low for reports (expensive)
new Worker('critical', processCritical, { connection, concurrency: 20 });
new Worker('email', processEmail, { connection, concurrency: 10 });
new Worker('reports', processReport, { connection, concurrency: 2 });
Resource tip:

Each worker connection to Redis counts. For many queues with low traffic, consider a single worker handling multiple queues with a QueueScheduler for delayed/repeatable jobs.
