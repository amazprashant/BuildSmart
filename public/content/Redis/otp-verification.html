OTP Verification with Redis

Use Redis to build a secure, time-limited OTP (One-Time Password) verification system. Redis's built-in TTL makes it the perfect store for ephemeral secrets.

Why Redis for OTP?

OTPs have two hard requirements: they must expire automatically and they must be retrieved instantly. Redis handles both perfectly:

  • TTL (Time To Live) — Redis natively expires keys after a set duration. No cron jobs needed.
  • In-memory speed — OTP lookups happen in sub-millisecond time.
  • Atomic operations — Set OTP and expiry in a single command; no race conditions.
Key insight:

Storing OTPs in a relational database requires a cleanup job to remove expired entries. Redis handles this automatically — when the TTL expires, the key is deleted.

OTP Flow

1

User requests OTP

User enters their phone/email. Backend generates a 6-digit OTP.

2

Store OTP in Redis

SETEX otp:+91XXXXXXXXXX 300 "482931" — stores OTP with 5-min TTL.

3

Send OTP to user

Backend sends OTP via SMS/email. User receives it on their device.

4

User submits OTP

User enters the OTP in the form. Backend receives the submission.

5

Verify & Delete

GET otp:+91XXXXXXXXXX — if match, delete key and mark user as verified.

Implementation (Node.js + ioredis)

import Redis from 'ioredis';
import crypto from 'crypto';

const redis = new Redis();

const OTP_TTL = 300; // 5 minutes
const OTP_KEY = (phone: string) => `otp:${phone}`;
const ATTEMPTS_KEY = (phone: string) => `otp_attempts:${phone}`;

// Step 1: Generate and store OTP
export async function sendOtp(phone: string): Promise {
  // Rate limit: max 3 OTP requests per 10 min
  const attemptsKey = ATTEMPTS_KEY(phone);
  const attempts = await redis.incr(attemptsKey);
  if (attempts === 1) await redis.expire(attemptsKey, 600);
  if (attempts > 3) throw new Error('Too many OTP requests. Try again later.');

  const otp = crypto.randomInt(100000, 999999).toString();
  await redis.setex(OTP_KEY(phone), OTP_TTL, otp);

  // TODO: Send OTP via SMS (Twilio, MSG91, etc.)
  console.log(`OTP for ${phone}: ${otp}`); // remove in production
}

// Step 2: Verify OTP
export async function verifyOtp(phone: string, inputOtp: string): Promise {
  const key = OTP_KEY(phone);
  const storedOtp = await redis.get(key);

  if (!storedOtp) throw new Error('OTP expired or not found. Please request again.');
  if (storedOtp !== inputOtp) throw new Error('Invalid OTP.');

  await redis.del(key); // delete after successful verification (one-time use)
  return true;
}

Key Patterns

Naming Convention

otp:{identifier}           → stores the OTP value
otp_attempts:{identifier}  → rate limiting counter

# Examples
otp:+919876543210          → "482931"  (TTL: 300s)
otp_attempts:+919876543210 → "2"       (TTL: 600s)

One-Time Use

Always delete after verification.

Once verified, immediately DEL the OTP key. This prevents replay attacks where the same OTP is used multiple times within the TTL window.

Resend Cooldown

// Check if OTP already exists (resend cooldown)
const existing = await redis.ttl(OTP_KEY(phone));
if (existing > 240) { // less than 60 seconds elapsed
  throw new Error(`Please wait ${existing - 240}s before requesting again.`);
}

Security Best Practices

Never expose OTPs in logs or responses.

Remove all console.log of OTP values in production. Log only events like "OTP sent" and "OTP verified".

  • Short TTL — 5 minutes is standard. Never more than 10 minutes.
  • Rate limiting — Max 3 requests per phone per 10 minutes.
  • One-time use — Delete key immediately after successful verification.
  • Cryptographic OTP — Use crypto.randomInt, not Math.random().
  • Constant-time compare — For high-security systems, use crypto.timingSafeEqual.
