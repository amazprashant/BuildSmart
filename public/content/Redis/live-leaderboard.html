Why Redis Sorted Sets?

A Sorted Set stores unique members, each with a floating-point score. Redis maintains them in score order automatically. This makes leaderboard operations trivially fast:

  • Update score: ZADD or ZINCRBY — O(log N)
  • Get top N players: ZREVRANGE — O(log N + M)
  • Get player rank: ZREVRANK — O(log N)
  • Get player score: ZSCORE — O(1)
Compare to SQL:

A SQL leaderboard requires ORDER BY score DESC LIMIT 10 — a full table scan or expensive index operation. Redis Sorted Sets are already sorted in memory.

REST API (Express + ioredis)

import Redis from 'ioredis';
import express from 'express';

const redis = new Redis();
const router = express.Router();
const LB_KEY = 'game:leaderboard';

// Add or update score
router.post('/score', async (req, res) => {
  const { playerId, score } = req.body;
  await redis.zadd(LB_KEY, score, playerId);
  res.json({ playerId, score });
});

// Increment score (e.g., on game event)
router.patch('/score/:playerId/add', async (req, res) => {
  const { amount } = req.body;
  const newScore = await redis.zincrby(LB_KEY, amount, req.params.playerId);
  res.json({ playerId: req.params.playerId, newScore: parseFloat(newScore) });
});

// Get top N players
router.get('/leaderboard/top/:n', async (req, res) => {
  const n = parseInt(req.params.n) - 1;
  const raw = await redis.zrevrange(LB_KEY, 0, n, 'WITHSCORES');

  const leaderboard = [];
  for (let i = 0; i < raw.length; i += 2) {
    leaderboard.push({
      rank: Math.floor(i / 2) + 1,
      playerId: raw[i],
      score: parseFloat(raw[i + 1]),
    });
  }
  res.json(leaderboard);
});

// Get single player's rank and score
router.get('/leaderboard/player/:playerId', async (req, res) => {
  const [rank, score] = await Promise.all([
    redis.zrevrank(LB_KEY, req.params.playerId),
    redis.zscore(LB_KEY, req.params.playerId),
  ]);

  if (rank === null) return res.status(404).json({ error: 'Player not found' });
  res.json({ playerId: req.params.playerId, rank: rank + 1, score: parseFloat(score!) });
});

Multiple Leaderboards

// Daily, weekly, all-time leaderboards
const date = new Date();
const DAILY_KEY  = `lb:daily:${date.toISOString().slice(0,10)}`;  // lb:daily:2024-03-15
const WEEKLY_KEY = `lb:weekly:${getISOWeek(date)}`;               // lb:weekly:2024-W11
const ALL_TIME   = 'lb:alltime';

// Update all three at once (pipeline for efficiency)
const pipeline = redis.pipeline();
pipeline.zincrby(DAILY_KEY, points, playerId);
pipeline.zincrby(WEEKLY_KEY, points, playerId);
pipeline.zincrby(ALL_TIME, points, playerId);
// Set daily TTL (auto-cleanup after 25 hours)
pipeline.expire(DAILY_KEY, 90000);
await pipeline.exec();
Auto-cleanup tip:

Set a TTL on time-based leaderboard keys. Daily boards expire after ~25 hours, weekly after ~8 days. Redis handles cleanup automatically — no cron jobs needed.
