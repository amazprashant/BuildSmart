Introduction to Redis

Redis (Remote Dictionary Server) is an open-source, in-memory data structure store used as a database, cache, message broker, and queue. Known for its blazing-fast performance and versatile data types.

What is Redis?

Redis is an in-memory key-value store that persists data on disk. Unlike traditional databases that read/write from disk, Redis keeps all data in RAM — making operations 10–100x faster than disk-based databases.

Core idea: Every operation in Redis is a key-value lookup. A key is always a string; a value can be one of many complex data types.
⚡

In-Memory Speed

All data in RAM. Sub-millisecond read/write latency.

💾

Persistence

RDB snapshots + AOF logs for durability when needed.

🔀

Rich Data Types

Strings, Hashes, Lists, Sets, Sorted Sets, Streams.

📡

Pub/Sub

Built-in publish/subscribe messaging for real-time events.

⏳

TTL Support

Set expiry on any key — great for caching and sessions.

🔗

Atomic Operations

All operations are atomic. Pipelines for batching.

Essential Commands

# String operations
SET user:1:name "Alice"
GET user:1:name
SETEX session:abc 3600 "token_xyz"   # set with 3600s TTL
INCR page:views                      # atomic counter

# Hash operations
HSET user:1 name "Alice" age 28 city "Mumbai"
HGET user:1 name
HGETALL user:1

# List operations (queue pattern)
LPUSH queue:emails "job1"            # push to head
RPOP queue:emails                    # pop from tail (FIFO)

# Key management
TTL session:abc                      # seconds remaining
EXPIRE session:abc 7200              # reset TTL
DEL user:1:name                      # delete key
EXISTS user:1:name                   # 1 or 0

Common Use Cases

🗂

Caching

Cache DB query results, API responses, HTML fragments to reduce load.

🔐

Session Store

Store user sessions with automatic TTL expiry.

📬

Job Queues

LPUSH/BRPOP for task queues; BullMQ uses Redis underneath.

🏆

Leaderboards

Sorted Sets maintain ranked scores in real-time.

📡

Pub/Sub

Real-time notifications, chat, live updates.

🔢

Rate Limiting

INCR + TTL for simple, fast rate limiting per user.

Persistence Modes

RDB (Redis Database): Point-in-time snapshots saved to disk at configured intervals. Compact, great for backups. Risk: data loss between snapshots.
AOF (Append-Only File): Logs every write operation. More durable (can be fsynced every second or on every write). Larger files, slower restarts.

Most production setups use both RDB + AOF for the best balance of performance and durability.
