The Two Approaches

📄 JSON String

  • Store entire object serialized as a string
  • Single key: user:123
  • Read/write the whole object at once
  • Nested objects supported natively
  • Requires parse/stringify on every operation

🗂 Redis Hash

  • Store each field as a hash field
  • Single key: user:123 with fields
  • Read/write individual fields efficiently
  • Only flat key-value pairs (no nesting)
  • Native Redis type — no serialization

JSON String Approach

// Store
const user = { id: '123', name: 'Alice', email: 'alice@example.com', plan: 'premium', loginCount: 47 };
await redis.setex(`user:${user.id}`, 86400, JSON.stringify(user));

// Read (entire object)
const raw = await redis.get('user:123');
const user = raw ? JSON.parse(raw) : null;

// Update (must read-modify-write entire object)
const raw = await redis.get('user:123');
const user = JSON.parse(raw!);
user.loginCount += 1;
await redis.setex('user:123', 86400, JSON.stringify(user));

// This is NOT atomic — race condition risk in concurrent updates!
Race condition warning:

Read-modify-write with JSON strings is NOT atomic. Two simultaneous requests can overwrite each other's changes. Use Redis transactions (MULTI/EXEC) or HASH with HINCRBY for counters.

Redis Hash Approach

// Store (HSET accepts field-value pairs)
await redis.hset('user:123', {
  name: 'Alice',
  email: 'alice@example.com',
  plan: 'premium',
  loginCount: '47',  // Redis stores all values as strings
  createdAt: new Date().toISOString(),
});
await redis.expire('user:123', 86400);

// Read all fields
const user = await redis.hgetall('user:123');
// user = { name: 'Alice', email: '...', loginCount: '47', ... }
// Note: all values are strings — parse numbers as needed
const loginCount = parseInt(user.loginCount);

// Read single field (efficient — no serialization)
const name = await redis.hget('user:123', 'name');
const email = await redis.hget('user:123', 'email');

// Update single field (atomic, no read-modify-write needed)
await redis.hset('user:123', 'plan', 'enterprise');
await redis.hset('user:123', 'updatedAt', new Date().toISOString());

// Atomic counter increment (no race condition!)
await redis.hincrby('user:123', 'loginCount', 1);

// Check if user exists
const exists = await redis.hexists('user:123', 'email');

When to Use Each

Use Redis Hash when:

Profile has many fields updated independently (status, counters, last-active). You need atomic field updates. Profile is queried frequently by individual fields. Memory efficiency matters at scale.

Use JSON String when:

Profile has nested objects (addresses, preferences object). You almost always read/write the whole object together. Profile is read-heavy and rarely updated. Simplicity matters more than partial-update efficiency.

Hybrid Approach (Best of Both)

// Store frequently-updated fields as Hash
await redis.hset('user:123', {
  name: 'Alice',
  plan: 'premium',
  loginCount: '0',
  lastSeen: new Date().toISOString(),
});

// Store complex nested data separately as JSON
await redis.setex('user:123:preferences', 86400, JSON.stringify({
  theme: 'dark',
  notifications: { email: true, push: false },
  language: 'en',
}));

// Update counter atomically
await redis.hincrby('user:123', 'loginCount', 1);
await redis.hset('user:123', 'lastSeen', new Date().toISOString());

// Read flat fields via HGETALL, complex data via separate GET
const [profile, prefs] = await Promise.all([
  redis.hgetall('user:123'),
  redis.get('user:123:preferences').then(v => v ? JSON.parse(v) : {}),
]);
